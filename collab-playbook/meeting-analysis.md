# Meeting Analysis — 회의록 분석과 프로파일 작성 절차

## 1. 분석 출력 형식

회의록(녹취 전사, 회의록, 채팅 로그)을 받으면 아래 순서로 정리한다. 상대 분석만 하고 끝내지 않는다 — 5번(내 쪽 문제)을 빼면 분석이 반쪽이다.

```
## 1. 상대가 지금 당장 요구하는 것
표: 항목 / 내용 / 비고(누가 하나, 기한)

## 2. 내 쪽 액션 아이템 (확인해서 회신하기로 한 것)
번호 목록. 각 항목에 "왜 상대가 이걸 묻는지"를 한 줄 붙인다.

## 3. 사후(다음 단계) 요구
반드시 계획에 넣어야 할 것. 상대가 명시적으로 "나중에", "끝나고" 라고 한 것.

## 4. 경계선 발언 (상대가 스스로 그은 선)
"이건 알 필요 없다", "이건 그냥 하시면 된다", "이건 미리 얘기해달라" 같은 발언을 원문 근처 표현으로 인용.
→ 이 발언들이 나중에 선을 그을 때 그대로 돌려줄 근거가 된다.

## 5. 내 쪽에서 상대가 불쾌·불합리하게 느꼈을 포인트
self-profile.md의 P1~P7과 대조. 새 패턴이면 번호를 추가한다.

## 6. 유형 판정
관측된 신호 → 유형 코드. 근거 발언을 최소 3개 인용. 반대 해석도 1개 이상 적는다.

## 7. 사용자 우려에 대한 솔직한 판정
사용자가 "이 사람이 X하려는 것 같다"고 하면: 근거가 되는 대목, 반대 근거, 내 판정, 그리고 사용자의 해석이 과잉인지 과소인지.
사용자 편을 들기 위해 판정을 흐리지 않는다.
```

## 2. 유형 판정 신호

| 신호 | 가리키는 유형 |
|---|---|
| "운영 책임이 나한테 있다", "나중에 뒤통수", "픽스 전에 같이" | OWNER-DESIGNER |
| "매니지드로 가야", "잘 알려진 방식으로 바꿔야", "바꿔야 돼요" | OWNER-DESIGNER (방향성 선점) |
| "내부 로직은 알 필요 없다", "블랙박스로 본다" | OWNER-DESIGNER의 자기 제한 — 좋은 신호. 인용해 둔다 |
| 체크리스트·규정·감사 언급, "이거 없으면 승인 안 된다" | GATEKEEPER |
| "요청서 주시면 그대로 하겠다", 배경 질문 없음 | TICKET-TAKER |
| "같이 과제로", "우리 팀 성과로도", 보고 라인 언급 | CO-OWNER |

한 사람이 두 유형의 신호를 보일 수 있다. 주 유형 + 부 유형으로 적는다.

## 3. 과잉 해석 / 과소 해석 판정 기준

**과잉 해석 징후** (사용자가 상대를 실제보다 위협적으로 보는 경우):
- 상대 요구가 회사 표준·보안 기준을 그 모듈에도 적용하겠다는 것뿐인데 "주도권 침해"로 읽음
- 상대가 스스로 범위를 좁힌 발언을 무시하고 훈계조 말투에 반응함
- 상대의 "설명해달라"가 실은 우리 쪽 설명 부족에서 온 것

**과소 해석 징후** (사용자가 위협을 놓치는 경우):
- 상대가 확정 문서 공유를 거절하고 "확정 전" 참여를 요구했는데 이를 협조로만 읽음
- 상대가 구조도 모르면서 아키텍처 방향("매니지드로")을 먼저 깔았는데 그냥 넘어감
- 사전 발언권을 범위 없이 계속 주고 있음 (누적되면 실질 결정권 이동)

판정은 "대부분 과잉이나 이 대목은 타당" 식으로 대목을 특정해서 말한다.

## 4. 프로파일 작성 절차 (새 인물 추가)

1. `profiles/_template.md`를 복사해 `profiles/<역할-식별자>.md`로 만든다. 실명 대신 역할+식별자(예: `infra-architect-A`)를 쓴다.
2. 위 분석 결과의 4(경계선 발언), 6(유형 판정)을 프로파일의 해당 절에 옮긴다.
3. "대응 전략"은 반드시 **지켜야 할 선 / 내줘도 되는 것 / 먼저 제안할 문장** 세 부분으로 쓴다.
4. "통하는 표현 / 안 통하는 표현"에 이번 회의에서 실제로 효과가 있었던·없었던 말을 적는다.
5. `collab-playbook/playbook.md` 의 프로파일 인덱스 표(§3)에 한 줄 추가한다.
6. 같은 인물과의 두 번째 회의 이후에는 "관측 이력" 절에 일자와 변화만 추가한다. 프로파일을 새로 만들지 않는다.

## 5. 인물이 아니라 팀 단위로 볼 것

같은 팀의 다른 사람이 나오면 팀 공통 특성(표준·보안 기준, 보고 체계, 일정 압박)은 팀 파일로 뺄 수 있다. 3명 이상 쌓이면 `profiles/team-<팀명>.md`를 만들고 개인 프로파일에서 참조한다.
