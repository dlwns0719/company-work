# weekly-report — 주간보고

## 목적

주간보고를 **이미 쌓인 기록에서 만들어 낸다.** 손으로 다시 쓰지 않는다.

| 재료 | 경로 |
|---|---|
| 일지 | `records/daily/YYYY-MM/YYYY-MM-DD-log.md` |
| 회의록 | `records/meetings/YYYY-MM/YYYY-MM-DD-*/minutes.md` |
| 할 일 목록 | `records/todo.md` |
| 과제 폴더 | `records/projects/<slug>/README.md` (근거 문서 이름) |
| 트래커 대기열 | `records/_system/queue/tracker-pending.md` |
| 설정 | `config/company.env` (`MY_NAME`·`TEAM_NAME`·`WEEKLY_UPLOAD_DIR`) |

산출물은 `records/weekly/YYYY/YYYY-Www.md` 다. 권장 시점은 설정의 `WEEKLY_REPORT_DOW` 요일 퇴근 전이다.

## 입력

`$ARGUMENTS` = `[기간]` (선택).

- 없으면 이번 주 월요일 ~ 오늘.
- `YYYY-MM-DD~YYYY-MM-DD` 형식이면 그 기간. 파일명 주차는 기간 시작일의 ISO 주차(`date -d <시작일> +%G-W%V`).

## Step

### Step 1 — 기간·대상 파일 확정

1. 기간과 주차를 정한다.
   ```bash
   START=$(date -d "$(date +%F) -$(( $(date +%u) - 1 )) days" +%F); END=$(date +%F)
   WEEK=$(date -d "$START" +%G-W%V)
   ```
2. 대상 파일이 있으면 Read 후 **갱신 여부를 묻는다.** 덮어쓰지 않는다.
3. **지난 주간보고가 빠졌는지 본다.** 직전 주의 파일이 없으면 보고하고, 그 주를 먼저 만들지 이번 주에 합칠지 묻는다.
4. 기간 내 평일 중 `holidays.txt` 에 없는 날을 근무일로 본다. 기간·근무일 수·대상 경로를 1~2줄로 보고한다.

### Step 2 — 재료 수집

1. 근무일별 일지를 읽는다. **일지가 없는 근무일**은 목록으로 보고하고 `/daily-log <날짜>` 로 먼저 채울지 묻는다.
   머리말이 `reviewed: false` 인 일지도 날짜 목록으로 보고한다. 그 블록은 재료로 쓰되 초안에서 미검토 일지에서 온 항목을 표시한다.
2. 기간 내 회의록의 `결정 사항`·`해야 할 일` 절만 뽑는다.
3. todo 의 각 섹션을 그대로 가져온다.
4. 대기열 `## 대기` 항목을 읽는다.
5. 재료 수(일지 n일, 회의록 n건, 할 일 n건, 대기열 n건)를 1줄로 보고한다.

### Step 3 — 주간보고 초안

`templates/weekly.md` 양식으로 채운다. 머리말의 이름·팀은 설정에서 가져온다.

- **할 일 ID 로 묶는다.** 여러 날 기록이 같은 `T-NNN` 을 가리키면 한 항목으로 합친다. ID 가 없는 항목은 과제 단위로 묶고
  `(할 일 목록에 없음)` 을 붙인다.
- **한 항목 = 한 줄 요약 + 근거.** 근거는 산출물 파일명, 트래커 번호, 회의록 절 중 있는 것. 읽는 사람이 열 수 없는 로컬 경로는 파일명만 적는다.
- `막힌 것 / 요청` 은 todo 의 `대기` 와 일지의 `블로커` 에서 온다. 누구에게 무엇을 요청하는지 쓴다.
- `AI 활용` 은 일지에서 확인된 것만 쓴다. 없으면 `- 없음`.
- **섹션 이름을 바꾸지 않는다.** 받는 쪽이 섹션 이름으로 모아 갈 수 있다.

초안을 화면에 보이고 수정 요청을 받는다. 확정되면 저장한다.

### Step 4 — 트래커 반영안

트래커를 쓰지 않으면(`TRACKER_NAME` 이 빔) Step 4·5 를 건너뛴다. **이 단계에서는 아무것도 쓰지 않는다.**

| 출처 | 반영안 종류 |
|---|---|
| 대기열 `## 대기` 항목 | 그대로 (`신규` / `코멘트` / `날짜` / `상태 제안`) |
| 이번 주 완료된 할 일 중 `트래커: #번호` 가 있는 것 | 완료 코멘트 + `상태 제안` |
| 이번 주 회의에서 나온 할 일 중 `트래커: -` 인 것 | `신규` 후보 (회의 결정 사항만) |

번호 매긴 표로 보인다: `번호 / 종류 / 할 일 ID / 트래커 번호 / 내용`. 사용자가 반영할 번호를 지정한다.

### Step 5 — 트래커 반영

지정분만 처리한다. 이 레포에는 트래커에 쓰는 도구가 기본으로 들어 있지 않다. 회사 브랜치에 그 회사 트래커용 스킬이 있으면
그것을 쓰고, 없으면 붙여 넣을 수 있는 문안을 항목별로 출력한다. 상태 변경은 사용자가 **명시한 항목만** 한다.
반영된 대기열 항목은 `## 반영 완료` 로 옮기고 `반영: YYYY-MM-DD` 를 붙인다.

### Step 6 — 할 일 목록 정리

1. `## 완료 (이번 주)` 와 `## 취소` 항목을 `## 지난 완료` 로 내린다. 옮기기 전에 목록을 보이고 확인받는다.
2. `(할 일 목록에 없음)` 항목 중 계속할 일이 있으면 새 ID 로 추가할지 묻는다.
3. 머리말 `updated` 를 오늘로 바꾼다.

### Step 7 — 올리기와 보고

`WEEKLY_UPLOAD_DIR` 가 설정돼 있으면 대상 경로와 올릴 내용을 보이고 **확인 후에만** 복사한다. 같은 파일이 있으면 덮어쓰지 않고
차이를 보인다. 그 폴더의 다른 파일은 고치지 않는다.

```text
주간보고: records/weekly/<연>/<WEEK>.md (항목 n개)
트래커 반영: 코멘트 n · 신규 n · 상태 변경 n · 보류 n
할 일 정리: 지난 완료로 n건 이동, 신규 n건
기록 없는 날: <없음 | 날짜 목록>
올리기: <대상 경로> (복사함 | 보류 | 설정 없음)
```

이어서 `guides/GUIDE_CORE.md` §5 Self-Check 를 출력한다.

## 금지

- 사용자 확인 전 트래커 쓰기·올리기 금지.
- 일지·회의록에 없는 성과를 지어내지 않는다.
- 기존 주간보고 덮어쓰기 금지 — 갱신은 확인 후.
- 양식의 섹션 이름 임의 변경 금지.
- 토큰 출력 금지.
