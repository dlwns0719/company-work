# meeting-intake — 회의 전사 → 회의록 + 할 일 갱신

## 목적

회의가 끝나면 전사 파일 하나로 다음을 끝낸다.

1. 회의 폴더 — `records/meetings/YYYY-MM/YYYY-MM-DD-<slug>/` 에 `minutes.md`(회의록)와 `transcript.txt`(전사 원문)
2. 회차 기록 — 이어지는 회의면 `records/meetings/series/<slug>.md` 갱신
3. 내 할 일 변경안 — `records/todo.md` 에 반영 (확인 후)
4. 트래커 등록안 — 회의에서 **결정된 일**만 (확인 후, 대기열에 적재)

## 입력

`$ARGUMENTS` = `[전사 파일 경로] [회의명]` (모두 선택).

- 경로가 없으면 `records/inbox/transcripts/` 의 파일을 최근 순으로 보이고 고르게 한다. 이 폴더에 있는 것은 모두 미처리다.
  하나뿐이면 그것으로 진행한다.
- 대화에 전사 원문을 붙여넣은 경우 그것을 입력으로 쓴다.
- 회의명이 없으면 그날 일정에서 후보를 찾고, 그래도 정해지지 않으면 묻는다.

회의명·참석자는 `records/_system/sources/outlook/<날짜>.md` 에서 먼저 찾는다. 전사 파일명의 시각과 겹치는 일정의 제목·주최·참석자가 후보다.
일정의 참석자 명단은 화자 대응의 후보일 뿐이다. 명단에 있다고 발언자로 단정하지 않는다.

## 보조 파일

| 파일 | 용도 | 없으면 |
|---|---|---|
| `records/_system/state/meetings.md` | 정기 회의별 참석자·주기·series 파일 | 회의명·참석자를 묻고, 정기 회의면 추가를 제안 |
| `records/_system/state/glossary.md` | 전사 오류 → 바른 표기 누적 사전 | `templates/glossary.md` 로 만든다 |
| `records/meetings/series/<slug>.md` | 이어지는 회의의 회차·누적 결정·이월 미결 | 두 번째 회차부터 `templates/meeting-series.md` 로 만든다 |

## Step

### Step 1 — 입력 확정

1. 전사 파일, 회의명, 날짜, 참석자를 확정한다. 날짜는 파일명·파일 수정 시각·사용자 발화 순으로 정한다.
2. `<slug>` 를 정한다. 회의명을 영문 소문자·하이픈으로 줄인 것이다(`weekly`, `kickoff`, `pipeline-handover-2`).
3. **이어지는 회의인가** — `meetings.md` 에 series 가 있거나, 같은 주제의 회의 폴더가 이미 있으면(이름 앞부분이 같고 번호만 다름)
   이어지는 회의다. 회차 기록을 Read 로 읽어 **이월 미결과 누적 결정을 먼저 파악한다.** 회의록 본문에서 그 항목이 어떻게 됐는지 추적하기 위해서다.
4. 회의 폴더를 만들고 전사를 `transcript.txt` 로 **옮긴다**(inbox 에서 사라져야 처리된 것으로 본다). 붙여넣은 원문이면 그대로 저장한다.
   inbox 에 전사와 이름이 같은 녹음 파일(`.webm` 등)이 있으면 같은 폴더에 `recording.<확장자>` 로 함께 옮긴다. 녹음은 git 에 올라가지 않는다.
   같은 폴더가 이미 있으면 덮어쓰지 않고 사용자에게 묻는다.
5. 회의명·날짜·참석자·원문 길이·회차를 1~2줄로 보고한다.

### Step 2 — 전사 보정

1. **화자 대응** — `SPEAKER_NN` 라벨마다 발언 내용으로 참석자를 추정해 표로 만든다:
   `전사 라벨 / 추정 인물 / 근거(발언 요지) / 확신도(높음·중간·낮음)`.
   - 근거는 역할 발언, 호칭, 담당 업무로 댄다.
   - 확신도 낮음인 라벨은 본문에 이름 대신 `참석자` 로 적는다. 이름을 추측으로 붙이지 않는다 — 회의록이 평가 근거가 될 수 있다.
   - 사용자 본인은 말이 적을 수 있다. 짧은 응답만 있는 라벨을 사용자로 단정하지 않는다.
2. **전사 오류 보정** — `glossary.md` 를 먼저 적용하고, 새로 찾은 오류를 표로 만든다. 확신 없는 것은 `[불명확]` 로 남긴다.
3. 두 표를 보이고 고칠 기회를 준다. "넘어가" 라고 하면 추정대로 진행한다.
4. 반복될 만한 보정(사람 이름, 과제명, 도구명)은 `glossary.md` 에 추가한다.

### Step 3 — 회의록 작성

`templates/meeting.md` 양식으로 `minutes.md` 를 쓴다.

- **주제별로 나눈다.** 시간 순서로 받아 적지 않는다. 같은 주제가 여러 번 나오면 한 절로 모은다.
- **구체적으로 쓴다.** 누가 무엇을 근거로 무엇을 주장했는지, 반론과 재반론까지 남긴다.
- 확정 발언과 검토 중 발언을 구분한다. 갈리지 않으면 `[확인 필요]`.
- 결정 사항·해야 할 일·미결은 표로 따로 모은다. 각 행에 본문 절 번호를 붙인다.
- 녹음이 중간에 시작하거나 끊겼으면 머리 부분에 밝힌다.
- 이어지는 회의면 머리말 `series:` 를 채우고, 지난 회차 이월 미결이 이번에 어떻게 됐는지 해당 절에 적는다.

저장 후 경로와 절 수를 보고한다.

### Step 4 — 회차 기록 갱신 (이어지는 회의만)

1. `## 회차` 에 이번 회차 한 줄을 더한다.
2. 이번 결정을 `## 누적 결정` 에 더한다. 앞 회차의 결정을 뒤집었으면 그 줄의 `뒤에 바뀌었나` 칸에 회차를 적는다. 지우지 않는다.
3. 이번에 해결된 이월 미결은 `해결 회차` 를 채우고, 새 미결을 더한다.
4. 첫 회차뿐인 회의는 만들지 않는다. 두 번째 회차를 처리할 때 첫 회차 회의록에서 거슬러 채운다.

### Step 5 — 할 일 변경안

1. 회의록의 `해야 할 일`·`결정 사항`·`미결` 에서 행동 항목을 뽑아 담당으로 분류한다: `나` / `팀 전체` / `다른 사람` / `불명확`.
2. todo 와 대조해 변경안을 만든다. **`나`·`팀 전체` 만** 대상이다.

   | 종류 | 조건 |
   |---|---|
   | 추가 | 목록에 없는 새 일 |
   | 변경 | 기존 항목의 기한·범위·지시자가 바뀜 |
   | 완료 | 회의에서 끝났다고 확인됨 |
   | 취소 | 회의에서 하지 않기로 함 |
   | 대기 | 다른 사람의 결정·자료를 기다려야 함 |

3. 표로 보인다: `번호 / 종류 / 할 일 ID / 내용 / 기한 / 근거(회의록 §절)`. `다른 사람`·`불명확` 은 표 아래 참고로만 적는다.
4. 사용자가 반영할 번호를 지정한다. **지정 전에는 todo 를 바꾸지 않는다.**
5. 새 항목의 `출처` 는 `meetings/<폴더> §<절>` 로 쓴다.

### Step 6 — 트래커 등록안

1. Step 5 에서 반영한 항목 중 **회의에서 결정된 일**이고 하루 이상 걸리는 것만 후보로 뽑는다. 잡무는 올리지 않는다.
2. 후보마다 `대기열` 또는 `안 올림` 을 받는다. `대기열` 이면 `records/_system/queue/tracker-pending.md` 에 `신규` 줄로 쌓는다.
3. 트래커를 쓰지 않는 회사(설정 `TRACKER_NAME` 이 빔)면 이 Step 을 건너뛴다.

### Step 7 — 보고

```text
회의록: records/meetings/<달>/<폴더>/minutes.md (절 n개)
회차 기록: series/<slug>.md (n회차, 이월 미결 n) | 해당 없음
화자: 확정 n / 추정 n / 미확정 n
할 일: 추가 n · 변경 n · 완료 n · 취소 n · 대기 n (보류 n)
트래커: 대기열 n · 안 올림 n
사전 추가: glossary n건
```

이어서 `guides/GUIDE_CORE.md` §5 Self-Check 를 출력한다.

## 금지

- 화자 확신도 낮음을 이름으로 단정하지 않는다.
- 사용자 지정 전 todo 변경·대기열 쓰기 금지.
- 기존 회의록 덮어쓰기 금지.
- 회의록·원문을 외부 서비스나 공유 페이지에 올리지 않는다. 회사 내부 자료다.
