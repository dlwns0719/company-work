# GUIDE_CORE — 공통 규칙

모든 슬래시 커맨드에서 작업 시작 전 먼저 로드한다.

---

## 1. 문서 작성 규칙

- **한다 체** — `~한다/~이다/~된다`. `~합니다/~입니다` 금지.
- **이모지 금지** — 마크다운 본문·코드·커밋 메시지 어디에도 이모지를 넣지 않는다.
- **섹션 번호 수동 부여 허용** — 이 프로젝트는 plain Markdown 아카이브다. `## 1. 개요` 처럼 직접 번호를 붙여도 된다. H2 가 3 개 이상인 긴 문서는 네비게이션·인용성을 위해 번호 부여를 권장한다. (Quarto 블로그 프로젝트와 달리 자동 번호 매기기가 없다.)
- **제목 계층 건너뛰기 금지** — `#` → `##` → `###` 순서로 사용한다. `##` 없이 `###` 부터 시작 금지.
- **코드 펜스 언어 식별자** — 코드 블록에 언어를 명시한다 (```` ```python ````, ```` ```bash ````, ```` ```yaml ````). 언어가 없으면 ```` ```text ```` 또는 식별자 없이 둔다.
- **파일명** — `kebab-case.md`. 한글·공백·대문자 금지.
- **메타데이터** — 새 문서 상단에 YAML 프론트매터 권장:
  ```yaml
  ---
  title: ...
  author: ...
  date: YYYY-MM-DD
  tags: [...]
  source: (원본 경로 또는 URL)
  ---
  ```

### 용어 선택 (한국 개발자 어휘)

기술 용어를 억지로 순우리말로 번역하지 않는다. 한국 개발자가 실제 대화에서 쓰는 형태로 쓴다.

**판정 기준**: "화이트보드 앞에서 동료에게 이 단어를 소리 내어 말하나?" 안 쓰는 말이면 바꾼다.

1. **통용되는 영어 용어는 그대로 둔다**(영어 또는 표준 외래어 표기). 새 한국어 합성어를 만들지 않는다.
   - X `입도 사다리` → O `분석 레벨` / `계층 레벨`
2. **영어 비유를 직역하지 않는다**(ladder · safety net · index · backstop). 비유를 버리고 개념만 쓴다.
   - X `책임 인덱스` → O `책임 목록` · X `안정망` → O `안전장치`
3. **낯선 전문어는 쉬운 말 + 괄호 병기**. 시니어가 실제로 쓰는 용어(팬아웃·휴리스틱 등)는 없애지 말고 이 형태로 남긴다.
   - `키워드 규칙(휴리스틱)` · `병렬 분석(팬아웃)`
4. **서술어·연결어만** 자연스러운 한국어로. 명사(개념)는 통용어를 유지한다.

참고 대응(자주 쓰는 것): `무상태 → 상태 없음(stateless)` · `유연 분류 → 자동 분류` · `오케스트레이션 → 조립/조율` · `결정론 → 항상 같은 결과(재현 가능)` · `트리거 → 발동 조건`.

### 번호 매기기 (일관성)

한 문서 안에서 목록·항목 번호 체계를 **하나로 통일**한다. 문자 라벨(`A1`·`B1`)·전역 정수(`1,2,3`)·중첩 십진(`4.C1`)을 **혼용하지 않는다**.

- 기본은 **전역 연속 정수** + **안정 정렬**(경로 사전순 등 재현 가능한 기준).
- 여러 소스(서브에이전트 등)를 합칠 때는 **합치는 쪽(메인)이 전역 기준으로 번호를 재부여**한다. 분할 과정의 그룹 라벨(A/B/C)은 산출 문서에 노출하지 않는다.

## 2. 검색/조회 규칙

- 근거가 없는 주장은 하지 않는다. 근거가 부족하면 "근거 부족" 또는 "모름" 으로 명시한다.
- 인용 시 파일 경로와 라인 번호를 `path:line` 형식으로 남긴다.

---

## 3. 파일 수정 규칙

- **수정 전 반드시 Read 도구로 파일 내용을 확인**한다. 추측으로 작성 금지.
- **기존 이름(변수·함수·파일) 보존** — 리팩터링 시 임의 변경 금지. 변경이 필요하면 사용자 확인 후 진행.
- **로직 축약 금지** — 동작하는 코드 구조를 요청 범위 밖에서 임의로 바꾸지 않는다.

---

## 4. 저장 위치 규칙

새 산출물의 저장 위치는 `GUIDE.md` §폴더 목록과 각 skill 가이드의 저장 규칙을 따른다.

---

## 5. Self-Check

작업 보고 전 아래 항목을 **출력**한다.

```
Self-Check:
- [ ] 한다 체 준수
- [ ] 이모지 없음
- [ ] 제목 계층·코드 펜스 언어 식별자 준수
- [ ] 근거 인용 (path:line)
- [ ] 용어: 억지 순우리말 번역·영어 비유 직역 없음(통용 영어 용어 유지, 낯선 전문어는 병기)
- [ ] 번호: 한 문서 내 번호 체계 통일(문자 라벨·정수·십진 혼용 없음)
- [ ] 파일 저장 위치 규칙 준수
```

## 6. 커밋·푸시

- 사용자가 명시적으로 요청할 때만 커밋·푸시한다.
- 커밋 메시지는 한국어 기반, 변경 의도(why) 중심. 이모지 금지.
