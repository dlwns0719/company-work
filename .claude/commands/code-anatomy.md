프로젝트 하네싱 체인에 따라 작업한다.

## 실행 순서

1. `GUIDE.md` 를 Read 로 읽는다 (라우팅 테이블).
2. `guides/GUIDE_CORE.md` 를 Read 로 읽는다 (공통 규칙).
3. `guides/code-anatomy.md` 를 Read 로 읽는다 (skill 본문 — 입도 사다리·6칸 동작명세·팬아웃 계약·Step·출력 템플릿).
4. code-anatomy.md 에 따라 실행한다.
   - Step 0 재현 기준 고정(커밋 해시·규모) → Step 1 분석 레벨 판별 → Step 2 책임 추출 → Step 3 병렬 분석 결정(대형이면 서브에이전트 병렬, 요약 없이 반환) → Step 4 책임별 6칸+다이어그램 작성 → Step 4.5 전체 조망 다이어그램 → Step 5 문서 조립·저장.
5. 모든 서술은 코드 근거 `path:line` 동반. 근거 없으면 `[추론]`/`[근거부족]` 표기.
6. 대상 코드는 고치지 않는다. 문서 파일 생성은 사용자 승인 후에만.

## 인자

- **대상 경로 [옵션]** (`/code-anatomy ~/workspace/<레포>/src/agents/<에이전트>`)
- `--out <경로>` 저장 위치 · `--scope <하위경로,...>` 일부만 분석
- **인자 없음** → 스킬 요약(분석 레벨·6칸·다이어그램·병렬 분석)을 보이고 대상 경로를 요청한 뒤 종료

사용자가 전달한 인자:

```text
$ARGUMENTS
```
