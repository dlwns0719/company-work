# 커뮤니케이션 직렬화 훈련 커리큘럼 (기준 문서)

> 목적: 사용자의 약점인 **"머릿속 논리를 상대가 이해할 수 있는 순서로 직렬화하지 못함"** 을
> 재작성 대행이 아니라 **의도적 연습(deliberate practice)** 으로 교정한다.
> `/comm-train` 스킬이 이 문서를 기준으로 훈련 루프를 운영한다. 기준이 바뀌면 이 파일만 고친다.
>
> 핵심 원칙(이게 다른 "글 고쳐주기"와 다른 점):
> 1. **모범답안을 먼저 주지 않는다.** 사용자가 직접 산출한 뒤에만 채점·교정한다.
> 2. **측정한다.** 매 세션 점수를 `progress-log.md` 에 누적해 습관 곡선을 본다.
> 3. **크기에 맞춘다.** 한 줄 질문에 7칸을 강제하지 않는다(§4 크기 적응).

---

## 1. 진단 기준선 (왜 이 훈련인가)

대화 데이터에서 반복 확인된 약점 5개다. 훈련은 이 5개를 레벨로 나눠 하나씩 잡는다.

| 코드 | 약점 | 데이터 근거(예) |
|---|---|---|
| W1 | 핵심 후치 — 결론·요청이 끝에 나옴 | 표·배경 먼저 깔고 요청은 맨 끝 |
| W2 | 전제 후행 — 상대가 맥락을 안다고 가정, 진짜 목적이 뒤늦게 등장 | "진짜 목적"이 47번째 메시지에 처음 등장 |
| W3 | 지시대명사 모호 — "이거/저거/그 부분/저기" | "이게 뭐야 이런 게 있었어?", "이폴더야 찾아줘" |
| W4 | 다중요구 혼재 — 한 메시지에 요구 여럿, 처리순서 불명확 | "빼고 / 둘로 나누고 / 공통부분 빼라" 한 덩어리 |
| W5 | 듣기 전 재프레이밍 — 상대 의도를 자기 틀로 치환 → 정정 연쇄 | "아니 내가 말한 건…" 정정이 반복 |

전제: 약점은 **사고력·이해력 부족이 아니라 출력 순서 습관**이다. 데이터상 구조화·추상화·자가검증은 강점으로 확인됐다. 훈련은 강점을 죽이지 않고 **출력 단계만** 교정한다.

## 2. 채점 루브릭 (객관·계량)

매 산출물을 6항목, 총 12점으로 채점한다. 가능한 한 **세는 기준**으로 둬 채점 일관성을 확보한다.

| 항목 | 0점 | 1점 | 2점 | 대응 약점 |
|---|---|---|---|---|
| R1 핵심 선행 | 결론/요청이 후반부 | 중반 | 첫 1~2문장 안 | W1 |
| R2 전제 명시 | 상대가 모를 정의·맥락 누락 | 일부만 | 필요한 전제 명시 | W2 |
| R3 지시대명사 | 모호 지시어 2개 이상 | 1개 | 0개(대상 식별자 명시) | W3 |
| R4 요청 분리 | 요구 2+ 인데 뭉침 | 번호만, 순서 모호 | 번호+처리순서 명시(요구 1개면 자동 2점) | W4 |
| R5 실행가능성 | 상대가 무엇을 할지 모름 | 추론 필요 | 바로 행동 가능 | W1·W4 |
| R6 분량 적정 | 핵심 대비 과다/과소 | 다소 | 크기 적응 준수(§4) | 전반 |

- **합격선**: 레벨별로 §3 에 명시. 기본은 해당 레벨 핵심 항목 만점 + 총점 9/12 이상.
- 채점 시 **감점 항목마다 한 줄 사유**를 붙인다(어디가 왜 깎였는지). 칭찬만 하거나 뭉뚱그리지 않는다.

## 3. 레벨 커리큘럼 (한 번에 하나, 누적)

기간은 고정 아님 — **합격 기준을 통과하면 다음 레벨로**, 못 하면 머문다(4주가 될 수도, 더 길 수도 있다). 상위 레벨은 하위 습관을 **누적 유지**한다(L3 에서도 R1 핵심 선행은 계속 채점).

### L1 — 핵심 선행 (W1)
- 목표: 모든 산출물의 첫 1~2문장 안에 결론 또는 요청.
- 드릴: 시나리오를 받아 첫 줄을 "결론:" 또는 "요청:" 으로 시작해 작성.
- 합격: 연속 3개 드릴에서 R1=2.

### L2 — 전제 명시 (W2)
- 목표: 상대가 모를 수 있는 정의·목적·제약을 본문 앞 한 줄로.
- 드릴: 일부러 맥락이 없는 시나리오를 주고, "전제:" 줄을 채워 작성.
- 합격: 연속 3개에서 R1=2 유지 + R2=2.

### L3 — 지시대명사 제거 + 요청 분리 (W3·W4)
- 목표: "이거/저거" 대신 식별자(파일명·항목명·번호) 명시, 요구 2+ 는 번호+순서.
- 드릴: 모호 지시어가 박힌 원문을 주고 대상 특정해 재작성 / 다중요구 시나리오 분해.
- 합격: 연속 3개에서 R1·R2 유지 + R3=2 + R4=2.

### L4 — 듣기 재진술 (W5)
- 목표: 반박·재질문 전에 상대 의도를 먼저 재진술("제가 이해한 요점은 A·B인데 맞나요?").
- 드릴: 코치가 모호하거나 함정 있는 "상대 발화"를 주면, 사용자는 정정·반박 전에 재진술문부터 작성.
- 합격: 연속 3개에서 재진술 선행 + 핵심 의도 정확히 포착.

### L5 — 통합 + 크기 적응 (전체)
- 목표: 실제 업무 메시지를 크기에 맞는 형식(§4)으로, 6항목 모두 충족.
- 드릴: 실제/실전형 메시지를 BLUF·중간·민토 중 적절한 형식으로.
- 합격: 연속 5개에서 총점 10/12 이상, 핵심 항목 무감점.

### L6 — 실전 유지 (졸업 후 루틴)
- 레벨 개념 없이, 사용자가 실제 보낼 메시지를 가져오면 채점·교정·로깅만 반복.
- 목적: 습관 고착. 점수 곡선이 떨어지면 해당 약점 레벨로 일시 복귀.

## 4. 크기 적응 규칙 (민토 스케일)

7칸을 모든 메시지에 강제하지 않는다. 메시지 복잡도로 형식을 고른다.

| 메시지 유형 | 형식 | 칸 |
|---|---|---|
| 한 줄 질문·지시 (슬랙/메신저) | **BLUF 1줄** | 결론/요청만 첫머리 ("요청: X. (대상 식별자 명시)") |
| 중간 (이유가 필요한 요청) | **BLUF + 기준** | 결론 → 요청 → 판단 기준 |
| 복잡 (보고·설계·요구사항·평가) | **민토 피라미드 풀** | 결론 → 근거(MECE 3개 내외) → 제외 조건 → 요청 / 필요 시 SCQA 도입부 |

원칙: **짧으면 짧게가 정답.** 데이터상 사용자 메시지의 약 69%가 100자 미만이다 — 여기에 7칸을 욱여넣으면 훈련이 일상에서 폐기된다. R6(분량 적정)은 이 규칙 위반을 잡는다.

---

## 5. 훈련 프로토콜 (의도적 연습 루프)

스킬은 매 드릴에서 아래 순서를 **반드시** 지킨다. 이 순서를 어기면(특히 1·2번) 재작성 대행으로 퇴행한다.

```text
1. 제시   코치가 시나리오(또는 사용자의 실제 초안)를 제시한다.
2. 산출   사용자가 직접 쓴다. 코치는 모범답안을 먼저 주지 않는다.   ← 핵심
3. 채점   §2 루브릭으로 항목별 점수 + 감점 사유 한 줄.
4. 분기   합격 못 하면 → 모범답안 대신 힌트(어느 항목을 어떻게)만 주고 2번으로(최대 3회).
         3회 후에도 미달이면 → 그제서야 모범답안 + 사용자안과의 차이 설명.
5. 기록   결과를 progress-log.md 에 append (§6 양식).
6. 종료   현재 레벨/연속 합격 카운트/다음 할 일 1줄 안내.
```

부속 규칙:
- **모범답안 선제공 금지.** 사용자가 최소 1회 산출하기 전에는 정답 문장을 보여주지 않는다.
- 드릴 소재는 사용자 도메인(Agent·RAG·LLM·DB 설계·커리어 판단·기술 문서)에서 생성한다. 가능하면 W1~W5 약점을 유발하도록 설계한다.
- 한 세션 분량은 기본 드릴 3개(또는 사용자가 가져온 실제 메시지 처리). 과하게 길게 끌지 않는다.

---

## 6. 진행 로그 양식 (progress-log.md append 규칙)

매 세션 종료 시 `comm-train/progress-log.md` 하단에 아래 한 블록을 추가한다. 날짜는 환경의 현재 날짜를 쓴다.

```md
## YYYY-MM-DD  (Lx)
- 드릴 수: N / 합격: M
- 항목 평균: R1 _ / R2 _ / R3 _ / R4 _ / R5 _ / R6 _  (총 __/12)
- 반복된 감점 패턴: (예: R1 핵심 후치 2회, R3 '이거' 사용 1회)
- 연속 합격 카운트: k  → (레벨 유지 / Lx+1 승급)
- 다음 세션 권장: (예: L2 계속 / 실전 메시지 가져오기)
```

추세 판정:
- 같은 레벨 핵심 항목이 **연속 3세션** 만점 → 승급.
- 졸업(L5 통과) 후 임의 세션에서 핵심 항목이 2회 연속 감점 → 해당 약점 레벨로 일시 복귀 후 재승급.

## 7. 모드 (인자)

`/comm-train [모드] [내용]`

| 모드 | 동작 |
|---|---|
| (없음) / `start` | progress-log 를 읽어 현재 레벨 파악 → 그 레벨 드릴 세션 운영 |
| `drill` | 현재 레벨 드릴 강제 시작 |
| `real <초안>` | 사용자가 실제 보낼 메시지를 가져옴 → §5 루프로 진단·자가수정·채점·로깅(실전 소재 훈련) |
| `status` | progress-log 요약: 현재 레벨, 점수 곡선, 반복 약점 |
| `crutch <초안>` | **목발 모드.** 급할 때 코치가 바로 재작성해 준다. 훈련 아님 → 로그에 점수로 기록하지 않음. 남용하면 치료가 안 된다는 경고 1줄 동반 |

`crutch` 와 나머지를 분리한 이유: 평소엔 자가 산출(치료), 마감 임박엔 재작성(목발). 둘을 섞으면 근육이 안 붙는다.

## 8. 프레임 이론 (참고 근거)

- **민토 피라미드(Barbara Minto)**: 결론을 맨 위에, 근거를 MECE 하게 묶어 아래로. W1·W4 의 표준 해법.
- **BLUF (Bottom Line Up Front)**: 첫 줄에 결론·요청. W1.
- **SCQA (상황-복잡-질문-답)**: 복잡한 글의 도입에서 전제를 앞세움. W2.
- **PREP (결론-근거-예시-결론)**: 말하기·보고용. W1.
- **Active restatement**: 상대 의도를 먼저 재진술해 확인. W5.

---

## 9. 금지

- 사용자가 산출하기 전에 모범답안을 보여주는 것(crutch 모드 제외).
- 점수 기록 없이 드릴만 돌리는 것(측정 누락 = 추세 소실).
- 한 줄 메시지에 7칸 템플릿을 강제하는 것(§4 위반).
- 약점을 사고력·이해력 문제로 단정하거나, 의학·심리 진단을 하는 것.
- 사용자 강점(구조화·자가검증)을 출력 교정 명목으로 깎아내리는 것.
